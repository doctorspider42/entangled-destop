# What `rust_protocol.py` generates Rust for. Read by `scripts/venus-gen.py`.
#
# Three sections. A line is one entry; `#` starts a comment; blank lines are
# ignored. Order within a section does not matter: output order follows the
# registry, so re-sorting this file changes nothing.
#
# [api]         The newest core Vulkan version whose structures a pNext chain
#               may carry. Structures of VK_VERSION_1_0 up to and including
#               this one are accepted in every chain that can name them.
#               Must agree with the `vk_xml_version` the capset advertises:
#               the guest's encoder gates 1.3+ chain structures on it
#               (`vn_protocol.py` get_type_condition), and a structure the
#               guest may send but we did not generate is fatal on arrival.
#
# [extensions]  Extensions whose structures chains may carry, on top of
#               [api]. Exactly this set is what info.rs publishes as the
#               *decodable* extension mask, which the capset is meant to
#               advertise so that the guest never encodes a structure this
#               host cannot decode (spec §6). Every name must be in
#               vn_protocol.py's VK_XML_EXTENSION_LIST.
#
# [commands]    Commands to generate args decoders and reply encoders for.
#               Every structure they reach — by member, by pointer, or through
#               a pNext chain permitted by the two sections above — is
#               generated with them. Transport commands (vk*MESA with a
#               context-stream role) are hand-written in venus/transport.rs
#               and are not listed here.
