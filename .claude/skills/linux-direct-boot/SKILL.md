# Direct Linux boot

Scope: backlog EPIC 2 (MVP-201…208) plus the bootstrap-kernel flow of EPIC 11.
Code lives in `crates/linux-boot`; addresses come from `machine_x86::layout`.

## Approach

Use the `linux-loader` crate (already a workspace dependency, feature
`bzimage`) — do not hand-roll ELF/bzImage parsing:

1. `linux_loader::loader::bzimage::BzImage::load()` loads the kernel into
   guest memory above `HIGH_RAM_START` and returns `bzimage_entry` and the
   setup header.
2. Initramfs: plain read + write into guest memory at a page-aligned address
   below the initrd address limit from the setup header
   (`initrd_addr_max`); record address and size in `boot_params`.
3. Cmdline at `layout::CMDLINE_START` (validated by `BootConfig::validate` —
   NUL-free, < `CMDLINE_MAX_LEN`), referenced from
   `boot_params.hdr.cmd_line_ptr`.
4. Zero page at `layout::ZERO_PAGE_START`: `boot_params` with
   `type_of_loader = 0xff`, E820 entries from `machine_x86::e820_map()`,
   initrd fields, and the setup header copied back from the load result
   (`linux-loader` has `configure_64bit_entry` helpers under
   `loader::x86_64` — prefer them).
5. vCPU0 starts in 64-bit mode at `bzimage_entry` with `rsi` = zero page GPA
   (see kvm-machine skill for the register/paging setup).

## Kernel command line policy

Base line for test/bootstrap guests:
`console=ttyS0 earlyprintk=serial panic=1 reboot=k`
Devices are announced with `virtio_mmio.device=…` clauses generated by
`virtio_core::mmio::cmdline_clause(slot_base, irq)` — one per populated slot.
Compose lines programmatically; never concatenate strings at call sites.

## Serial console (MVP-205/206)

- 16550 UART from the `vm-superio` crate at ISA `0x3f8`, IRQ 4, wired through
  `KVM_EXIT_IO` port handling.
- Output goes to a pluggable sink: stdout for `vmhost run`, a capture buffer
  for tests. The capture path is what boot tests scan for markers.

## Boot tests (MVP-207/208)

- `linux_boot::GUEST_READY_MARKER` ("VMHOST_GUEST_READY") is printed by test
  initramfs images once `/init` runs. Tests wait for it with a deadline;
  missing marker or a kernel panic string ("Kernel panic - not syncing")
  fails the test with the full captured serial log attached to the failure.
- Test kernels/initramfs are *artifacts*, not repo blobs: `guest/` holds the
  reproducible build configs (EPIC 11 MVP-1102), CI caches the built outputs.
  Never commit multi-megabyte binaries to git.

## Pitfalls

- `boot_params` must be zeroed before filling — stale bytes in reserved
  fields make kernels reject the boot (`sentinel` field logic in newer
  kernels: set `sentinel = 0` explicitly, it defaults to 0xff in some copies
  of the header!).
- Initramfs placement too high (above `initrd_addr_max`) silently fails on
  some kernels; always honor the header limit.
- `panic=1 reboot=k` makes panics terminate the VM quickly — keep both in
  test profiles so hung tests fail fast instead of timing out.
